# 命令参考

每条命令的作用、用法、示例与说明。Telegram 中的 `/help` 菜单提供同样的
命令 — 点一下即可收到对应章节。

## 会话

### /new

**作用**:在你选择的项目中创建新会话，其 Telegram 主题随即打开。

**用法**:`/new <标题?>`

**示例**:
- `/new 销售分析` → 显示项目选择器；点击一个，便在那里创建“销售分析”会话
- `/new` → 先在聊天中询问标题，给出后显示选择器

**说明**:
- 当前对话的项目排在选择器首位（✅）— 它是默认值：点一下即可。
- “➕ 新项目…”会询问名称，并在当前项目旁创建该文件夹；会话在其中打开。
- 主题在创建时即打开（以前是随第一条消息诞生）：在里面写，会话就已经在听了。
- 你在新主题中选择提供商和模型：它停在项目默认模型所属的提供商处，该模型标有 ✅ — 点一下保留，或浏览其他。之后用 `/models` 也一样。
- 若 `/new` 不带标题，10 分钟内在该主题中写的下一条消息就是名称。

### /use

**作用**:决定聊天根部的消息发往哪个会话。

**用法**:`/use <ses_id>`

**示例**:
- `/use ses_f2a05826affeXDqtDAtfF23Rud` → 根部指向该会话
- `/use` → 显示当前会话

**说明**:主题中的消息总是发往该主题的会话，与 `/use` 无关。

### /fork

**作用**:把会话分叉到其最后一条消息 — 在不弄脏原会话的前提下尝试想法。

**用法**:`/fork`（在主题中）或 `/fork <ses_id>`

**示例**:
- 在会话主题中 `/fork` → 创建分叉并通知你
- `/fork ses_xxx` → 从任何地方同样可行

**说明**:分叉是带有自己主题的新会话。原会话保持不变。

### /rename

**作用**:重命名会话 — Telegram 主题和桌面端会跟随更改。

**用法**:`/rename <标题>` 或 `/rename <ses_id> <标题>`

**示例**:
- `/rename Q4 分析` → 重命名该主题的会话
- `/rename`（不带标题）→ 从对话记录中建议 3 个标题，点一下选择

**说明**:标题被截断至 128 个字符（Telegram 的主题名称上限）。

### /detach

**作用**:把聊天根部与其会话解耦 — 你在那里写的内容不再发往任何会话。

**用法**:`/detach`

**示例**:
- `/detach` → 根部变为自由
- `/use <ses_id>` → 重新耦合

**说明**:会话主题不受影响。

### /archive

**作用**:归档该主题的会话 — 在私聊中会删除主题并使会话静音。

**用法**:`/archive` 或 `/archive <ses_id>`

**示例**:
- 在某个主题中 `/archive` → 主题从聊天中消失
- `/archive ses_xxx` → 从任何地方同样可行（id 接受唯一前缀）

**说明**:`/unarchive` 会把它带回来 — 单独使用会打开已归档会话的选择器，因此不需要 id。

### /unarchive

**作用**:唤醒已归档的会话 — 不带 id 时打开选择器；带文本时按项目、标题或 id 搜索。

**用法**:`/unarchive`、`/unarchive <文本>` 或 `/unarchive <ses_id>`

**示例**:
- 在根部 `/unarchive` → 打开已归档会话的选择器，最近的在前
- `/unarchive 发票` → 与之匹配的（标题、项目或 id）选择器
- `/unarchive ses_ed2c` → 按前缀解析 id 并直接唤醒
- 在活跃主题中 `/unarchive` → 提示该会话未被归档

**说明**:
- 不带 id 也不用猜：选择器以按钮列出已归档会话（标题 · 项目 · 活跃度），每页 8 条。
- `<文本>` 可作为按**项目**（文件夹名）、标题或 id 前缀的搜索。
- id 接受完整或唯一前缀形式，不区分大小写。
- 若主题已被删除，会以当前标题创建新的。
- 在私聊中 `/archive` 删除主题，因此 `/unarchive` 会重建它；PC 上的会话绝不会被触碰。

### /delthread

**作用**:删除论坛主题，但不触碰会话。

**用法**:`/delthread` 或 `/delthread <ses_id>`

**示例**:
- 在某个主题中 `/delthread` → 主题消失

**说明**:会话继续存在 — 其下一个事件会重建主题。要静音它：`/archive`。id 接受唯一前缀，不区分大小写。

### /rebuild

**作用**:删除所有会话主题并干净地重建论坛。

**用法**:`/rebuild`（带内联确认）

**示例**:
- `/rebuild` → 删除已映射的主题（逐个并确认），并重建你最近用过的那些（最多 12 个，最近的在前）

**说明**:旧消息不会重新导入 — `/export` 可下载每个会话的对话记录。只为最近 `rebuildIdleHours`（默认 24 小时）内用过的会话重建主题：服务器在重启时改写所有会话的 `updated` 字段，因此按它排序会让几天没人动过的会话复活；`idle` 才是真实的最后活跃。每次删除在忘记映射前都会确认 — 若 Telegram 拒绝某条（限流、断连），该主题保持映射，下一次 `/rebuild` 会重试；主题幸存的会话不会被复制。**孤儿**主题（无映射）无法自行清理：Bot API 没有“列出主题”，因此需要手动删除一次。

## 文件与代码

### /ls

**作用**:浏览会话项目的文件。

**用法**:`/ls [文件夹]`

**示例**:
- `/ls` → 列出项目根目录
- `/ls src` → 进入 src 文件夹
- 点击文件 → 下载它
- 在文本文件上 📎 → 把它附加到下一条消息

**说明**:按钮的索引会过期 — 若点击后提示“列表已过期”，重新打开 `/ls`。

### /find

**作用**:按名称模糊搜索文件。

**用法**:`/find <文本>`

**示例**:
- `/find navbar` → 名称中含 “navbar” 的文件
- `/find .test.` → 名称中含 “.test.” 的文件

**说明**:在会话的整个项目中搜索。

### /git

**作用**:代理在项目中动了什么 — 带 `+/−` 的状态和可下载的 diff。

**用法**:`/git`

**示例**:
- `/git` → 项目状态
- “查看 diff” → 预览 + 可下载的 `.patch`

**说明**:这是项目的 diff，不是会话的 — 多个代理可以共享。

### /revert

**作用**:撤销会话的上一轮（需确认）。

**用法**:`/revert` 或 `/revert <ses_id>`

**示例**:
- 在某个主题中 `/revert` → 提议撤销上一轮
- 用按钮确认 → 轮次被撤销

**说明**:只撤销上一轮。要多条：重复 `/revert`。

### /export

**作用**:以 JSON 下载会话的完整对话记录。

**用法**:`/export` 或 `/export <ses_id>`

**示例**:
- 在某个主题中 `/export` → 对话记录的 JSON 到达你这里
- `/export ses_xxx` → 从任何地方同样可行

**说明**:会话在 PC 上打开时导出完整。关闭时磁盘上可能没有对话记录（服务器的持久化缺陷）。

### /sh

**作用**:在会话**内部**运行 shell 命令 — 在后台，不打扰代理。

**用法**:`/sh <命令>`

**示例**:
- `/sh node -v` → `v24.21.0`
- `/sh git status` → 仓库状态
- `/sh ls` → 目录内容

**说明**:会话的 shell 是 PowerShell — `&&` 不可用，请使用 `;`。输出会到达主题。

**受保护的命令**:命令会被**解析**（而不是用正则搜索：真实名称，并解析别名），并落入三级之一：

- **直接放行**:纯读取（`Get-*`、`Test-*`、`ls`、`cat`）与开发工具链（`git`、`node`、`npm`、`cargo`、`python`...）。这里的误报会让机器人在每次 `git status` 前请求确认。
- **请求确认**:可恢复但可能切断服务或离开机器的操作 — 重启服务器、终止进程、安装软件、网络调用、远程执行、计划任务。卡片**解释每条命令做什么**（会发生什么，而不仅是文本），并且需要点“确认并执行”。待定项在执行**之前**被清除，因此崩溃不会重新触发它。
- **阻止，无例外**:不可逆的操作 — 格式化与擦除磁盘、引导与系统恢复、注册表、用户与凭据、密钥（`.env`、`.ssh`、浏览器配置文件、`Env:` 盘）、防御（杀毒、防火墙、BitLocker）、删除日志，以及所有逃逸向量（`iex`、`Invoke-Command`、嵌套 `powershell`/`cmd`、`-EncodedCommand`、`Add-Type`、直接访问 .NET/COM、定义函数与别名）。即使确认也不会执行：那是 PC 控制台的用途。

删除受**路径限制**:`Remove-Item`（以及 `rm`、`del`、`rmdir`...）允许在项目文件夹内 — 写代码的代理必须能删除 `node_modules` — 在外面则阻止。删除整个项目（`.`）或 `.git` 需要确认。

**为什么**（2026-10-07 事件）：`/sh opencode service restart` 杀死了托管插件的进程；由于 poll 偏移量只在内存中，Telegram 在每次重启时重发 update，服务器进入约 10 秒的循环，直到手动停用插件。持久的偏移量是解药；这个守卫是预防。

### /note

**作用**:在对话记录中留下备注 — 代理会在下一轮读到它，现在不会被唤醒。

**用法**:`/note <文本>`

**示例**:
- `/note 优先处理销售模块` → 代理把它当作上下文

**说明**:这是合成消息 — 它不会运行代理。

### /turns

**作用**:会话的各轮改变了什么 — 比 `/git` 更细。

**用法**:`/turns` 或 `/turns <ses_id>`

**示例**:
- 在某个主题中 `/turns` → 各轮的变更

**说明**:若服务器没有记录轮次变更，可能为空。

## 项目与配置

### /config

**作用**:读取并编辑项目的 `opencode.jsonc` — 新会话的默认模型。

**用法**:`/config` 或 `/config model <提供商/模型>`

**示例**:
- `/config` → 显示当前配置
- `/config model nvidia/z-ai/glm-5.3` → 更改默认（实时重载）

**说明**:更改适用于**新**会话 — 无需重启服务器。

### /worktree

**作用**:列出项目的工作树或创建新的。

**用法**:`/worktree` 或 `/worktree new <名称>`

**示例**:
- `/worktree` → 带按钮的列表，可打开各工作树中的会话
- `/worktree new feature-x` → 创建工作树

**说明**:点击工作树以在其中打开会话。

### /move

**作用**:把会话移动到另一个项目。

**用法**:`/move <目录>`

**示例**:
- `/move E:\Projects\Other` → 主题中的会话被移动到该项目

**说明**:Telegram 主题保持不变 — 只有工作目录改变。

### /mcp

**作用**:列出 MCP 服务器或连接/断开一个。

**用法**:`/mcp` 或 `/mcp connect|disconnect <server>`

**示例**:
- `/mcp` → 带状态的列表（🟢 已连接 / 🔴 未连接）
- `/mcp disconnect abap-docs` → 断开它
- `/mcp connect abap-docs` → 重新连接

**说明**:添加新服务器（PUT）仍由 PC 完成。

### /commands

**作用**:列出配置中的自定义命令或运行一个。

**用法**:`/commands` 或 `/commands run <文本>`

**示例**:
- `/commands` → 列表（init、review 等）
- `/commands run init` → 在主题的会话中运行命令 “init”

**说明**:自定义命令在项目的 `opencode.jsonc` 中定义。

## 信息与调试

### /locale

**作用**:切换机器人的语言 — `/help` 菜单、卡片和所有消息会立即跟随。

**用法**:`/locale`（带按钮）或 `/locale <es|en|pt|de|fr|it|id|ru|tr|zh>`

**示例**:
- `/locale` → 每种语言一个按钮的卡片（当前者带 ✓）
- `/locale zh` → 直接切换；确认以所选语言到达

**说明**:选择持久保存在 `~/.opencode/tg/locale.txt` — 重启不会丢失。`.env` 中的 `TG_LOCALE` 只是初始值。一门新语言就是 `CATALOGS`（src/locale.ts）中的一个新对象，加上它的 `COMMANDS.<语言>.md` — 无需额外代码。

### /bots

**作用**:显示多机器人布局：哪个机器人镜像哪个项目或会话、谁空闲，以及覆盖其余部分的主机器人（Hub）。

**用法**:`/bots`

**示例**:
- `/bots` → 每个机器人一行，带其认领（项目、会话或“空闲”）和活跃拓扑

**说明**:额外的机器人以 `TELEGRAM_BOT_TOKEN_<名称>` 在 `~/.opencode/tg/.env` 中声明 — 绝不在仓库中。拓扑（`single` / `per-project` / `per-session`）与显式指派（`assign`）位于 `config.json` 的 `"bots"` 块中。只有一个机器人时，卡片会说明如何再加一个。每个额外机器人都需要在 BotFather 启用 topics，与主机器人一样。

### /release

**作用**:把**这个**机器人还给池子 — 仅在 `per-session` 拓扑中。它的会话回到 Hub，直到另一个机器人认领它。

**用法**:`/release`（从你想释放的机器人的聊天中）

**示例**:
- `/release` → “🧹 已释放 — 它的会话回到 Hub”

**说明**:当你归档（`/archive`）认领它的会话时，机器人也会自行返回。在 `single` 和 `per-project` 中，该命令会回答不适用。会话重新激活时，其下一轮会自动认领一个空闲机器人。

### /context

**用法**:`/context` 或 `/context <ses_id>`

**示例**:
- 在某个主题中 `/context` → 该会话的上下文使用情况

**说明**:若服务器负载没有携带模型，则从对话记录中恢复。

### /usage

**作用**:会话的 token 和成本，含提供商与模型。

**用法**:`/usage` 或 `/usage <ses_id>`

**示例**:
- 在某个主题中 `/usage` → `🧪 nvidia · z-ai/glm-5.3 · 代理 build` + token

**说明**:模型和代理在负载忘记它们时从对话记录中恢复。

### /history

**作用**:会话对话的结尾。

**用法**:`/history` 或 `/history <ses_id>`

**示例**:
- 在某个主题中 `/history` → 最近 16 条消息

**说明**:从服务器（活跃会话）或磁盘上的对话记录读取。

### /log

**作用**:会话的服务器端日志的一节。

**用法**:`/log` 或 `/log <ses_id>`

**示例**:
- 在某个主题中 `/log` → 日志的最近 10 条事件

**说明**:这是一个读取窗口 — 不是完整日志。

### /ci

**作用**:显示仓库最近的 GitHub Actions 运行 — 哪个工作流、在哪个提交上、绿还是红。它证明一次推送完整到达：类型检查、测试套件，以及每周两次的依赖封印。

**用法**:`/ci`、`/ci <n>` 或 `/ci <工作流>`

**示例**:
- `/ci` → 最近 6 次运行及其状态和指向 sha 的链接
- `/ci 12` → 最近 12 次
- `/ci deps` → 仅 `deps-audit` 工作流的运行

**说明**:无依赖地读取 GitHub REST API。仓库是公开的，因此无需令牌即可工作（每 IP 每小时 60 次请求）；`~/.opencode/tg/.env` 中的 `GITHUB_TOKEN` 会提高限额并到达私有仓库。默认仓库是 `par4987/opencode-tg` — fork 可通过 `config.json` 中的 `"ci": { "repo": "owner/repo" }` 或 `TG_CI_REPO` 更改。

### /help

**作用**:列出命令并提供查看各自详情的菜单。

**用法**:`/help`

**示例**:
- `/help` → 简短列表 + 键盘
- 点击命令 → 其详细章节（作用、用法、示例、说明）

### /watch

**作用**:控制聊天中监视哪些会话。

**用法**:`/watch <id|all|off>`

**示例**:
- `/watch all` → 监视全部
- `/watch ses_xxx` → 只监视它
- `/watch off` → 不监视任何

**说明**:在配置为 `mirror: all` 时，`/watch <id>` 使其余静音。
