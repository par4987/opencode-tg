# Справочник команд

Каждая команда — что делает, как используется, с примерами и заметками. Меню
`/help` в Telegram предлагает те же команды — тапни одну и получишь её
раздел.

## Сессии

### /new

**Что делает**: Создаёт новую сессию в выбранном тобой проекте, с сразу же открытым тредом в Telegram.

**Использование**: `/new <название?>`

**Примеры**:
- `/new Анализ продаж` → показывает пикер проектов; тап по одному создаёт сессию «Анализ продаж» там
- `/new` → спрашивает название в чате и, после ввода, показывает пикер

**Заметки**:
- Проект текущего разговора идёт в пикере первым (✅) — это дефолт: одного тапа достаточно.
- «➕ Новый проект…» спросит имя и создаст эту папку рядом с текущим проектом; сессия откроется внутри.
- Тред открывается в момент создания (раньше рождался первым сообщением): напиши в него — и сессия уже слушает.
- Провайдера и модель выбираешь в новом треде: открывается на провайдере дефолтной модели проекта, с этой моделью отмеченной ✅ — тап сохраняет её, либо листай дальше. То же самое потом через `/models`.
- Если `/new` отправлен без названия, следующее сообщение в этом треде в течение 10 минут станет именем.

### /use

**Что делает**: Определяет, в какую сессию идут сообщения из корня чата.

**Использование**: `/use <ses_id>`

**Примеры**:
- `/use ses_f2a05826affeXDqtDAtfF23Rud` → корень указывает на эту сессию
- `/use` → показывает текущую сессию

**Заметки**: Сообщения в треде всегда идут сессии этого треда, независимо от `/use`.

### /fork

**Что делает**: Ветвит сессию до её последнего сообщения — пробуй идеи, не пачкая оригинал.

**Использование**: `/fork` (в треде) или `/fork <ses_id>`

**Примеры**:
- `/fork` в треде сессии → создаёт форк и сообщает
- `/fork ses_xxx` → то же самое откуда угодно

**Заметки**: Форк — новая сессия со своим тредом. Оригинал остаётся нетронутым.

### /rename

**Что делает**: Переименовывает сессию — тред в Telegram и десктоп следуют изменению.

**Использование**: `/rename <название>` или `/rename <ses_id> <название>`

**Примеры**:
- `/rename Анализ Q4` → переименовывает сессию из этого треда
- `/rename` (без названия) → предлагает 3 названия из транскрипта, выбираешь одним тапом

**Заметки**: Название обрезается на 128 символах (лимит Telegram на имя топика).

### /detach

**Что делает**: Отвязывает корень чата от его сессии — что ты там напишешь, больше не уйдёт ни в одну сессию.

**Использование**: `/detach`

**Примеры**:
- `/detach` → корень свободен
- `/use <ses_id>` → привязывает обратно

**Заметки**: Треды сессий не затрагиваются.

### /archive

**Что делает**: Архивирует сессию из треда — в приватном чате удаляет тред и глушит сессию.

**Использование**: `/archive` или `/archive <ses_id>`

**Примеры**:
- `/archive` в треде → тред исчезает из чата
- `/archive ses_xxx` → то же самое откуда угодно (id принимает уникальный префикс)

**Заметки**: `/unarchive` возвращает её назад — без аргументов открывает пикер архивных, так что id не нужен.

### /unarchive

**Что делает**: Будит архивную сессию — без id открывает пикер; с текстом ищет по проекту, названию или id.

**Использование**: `/unarchive`, `/unarchive <текст>` или `/unarchive <ses_id>`

**Примеры**:
- `/unarchive` в корне → открывает пикер с архивными сессиями, свежие впереди
- `/unarchive счета` → пикер с теми, что совпадают (название, проект или id)
- `/unarchive ses_ed2c` → разбирает id по префиксу и будит напрямую
- `/unarchive` в живом треде → сообщает, что эта сессия не в архиве

**Заметки**:
- Без id гадать не нужно: пикер перечисляет архивные кнопками (название · проект · активность), страницами по 8.
- `<текст>` работает как поиск по **проекту** (имени папки), названию или префиксу id.
- id принимается целиком или уникальным префиксом, без учёта регистра.
- Если тред был удалён, создаётся новый с текущим названием.
- В приватном чате `/archive` удаляет тред, поэтому `/unarchive` пересоздаёт его; сессию на ПК никто не трогает.

### /delthread

**Что делает**: Удаляет тред форума, не трогая сессию.

**Использование**: `/delthread` или `/delthread <ses_id>`

**Примеры**:
- `/delthread` в треде → тред исчезает

**Заметки**: Сессия продолжает существовать — её следующее событие пересоздаёт тред. Чтобы её заглушить: `/archive`. id принимает уникальный префикс, без учёта регистра.

### /rebuild

**Что делает**: Удаляет ВСЕ треды сессий и перестраивает форум начисто.

**Использование**: `/rebuild` (с инлайн-подтверждением)

**Примеры**:
- `/rebuild` → удаляет размапленные треды (по одному, с подтверждением) и пересоздаёт те, которыми ты пользовался недавно (до 12, свежие сверху)

**Заметки**: Старые сообщения заново не импортируются — `/export` выгрузит транскрипт каждой сессии. Треды пересоздаются только для сессий, использованных за последние `rebuildIdleHours` (по умолчанию 24 ч): сервер при рестарте перезаписывает поле `updated` у всех сессий, поэтому сортировка по нему воскрешала сессии, к которым никто не прикасался днями; `idle` — это последняя реальная активность. Каждое удаление подтверждается, прежде чем маппинг забывается — если Telegram отклоняет одно (rate limit, обрыв), тред остаётся в маппинге, а следующий `/rebuild` повторит попытку; сессия, чей тред выжил, не дублируется. **Осиротевшие** треды (без маппинга) сами не чистятся: у Bot API нет «списка топиков», поэтому их надо удалить вручную ровно один раз.

## Файлы и код

### /ls

**Что делает**: Навигирует по файлам проекта сессии.

**Использование**: `/ls [папка]`

**Примеры**:
- `/ls` → выводит корневой каталог проекта
- `/ls src` → заходит в папку src
- Тапни файл → скачивает его
- 📎 на текстовом файле → прикрепляет его к следующему сообщению

**Заметки**: Индексы кнопок протухают — если тап пишет «листинг устарел», открой `/ls` заново.

### /find

**Что делает**: Нечёткий поиск файлов по имени.

**Использование**: `/find <текст>`

**Примеры**:
- `/find navbar` → файлы, в имени которых есть «navbar»
- `/find .test.` → файлы с «.test.» в имени

**Заметки**: Ищет по всему проекту сессии.

### /git

**Что делает**: Что агент затронул в проекте — статус с `+/−` и скачиваемый diff.

**Использование**: `/git`

**Примеры**:
- `/git` → статус проекта
- «Посмотреть diff» → предпросмотр + скачиваемый `.patch`

**Заметки**: Это diff проекта, а не сессии — его могут делить несколько агентов.

### /revert

**Что делает**: Отменяет последний ход сессии (с подтверждением).

**Использование**: `/revert` или `/revert <ses_id>`

**Примеры**:
- `/revert` в треде → предлагает отменить последний ход
- Подтверждаешь кнопкой → ход отменяется

**Заметки**: Отменяется только последний ход. Для нескольких: повторять `/revert`.

### /export

**Что делает**: Выгружает полный транскрипт сессии в JSON.

**Использование**: `/export` или `/export <ses_id>`

**Примеры**:
- `/export` в треде → JSON транскрипта приходит тебе
- `/export ses_xxx` → то же самое откуда угодно

**Заметки**: С открытой на ПК сессией экспорт полный. В закрытой транскрипта на диске может не быть (баг персистентности сервера).

### /sh

**Что делает**: Запускает shell-команду ВНУТРИ сессии — в фоне, не будоража агента.

**Использование**: `/sh <команда>`

**Примеры**:
- `/sh node -v` → `v24.21.0`
- `/sh git status` → статус репозитория
- `/sh ls` → содержимое каталога

**Заметки**: Shell сессии — это PowerShell: `&&` в нём не работает, используй `;`. Вывод приходит в тред.

**Защищённые команды**: команда **парсится** (не ищется регуляркой — реальные имена, с разрешёнными алиасами) и падает на один из трёх уровней:

- **Проходит сразу**: чистое чтение (`Get-*`, `Test-*`, `ls`, `cat`) и девелоперский инструментарий (`git`, `node`, `npm`, `cargo`, `python`...). Ложное попадание заставило бы бота спрашивать подтверждение перед каждым `git status`.
- **Просит подтверждения**: восстановимое, но способное порвать службу или покинуть машину — рестарт сервера, убийство процессов, установка софта, сетевые вызовы, удалённый запуск, плановые задачи. Карточка **объясняет, что делает каждая команда** (что произойдёт, а не просто текст), и нужно тапнуть «Подтвердить и выполнить». Ожидание снимается **до** выполнения, так что краш его не перезапустит.
- **Блокируется без исключений**: то, что не имеет обратного пути — форматирование и стирание дисков, загрузка и восстановление системы, реестр, пользователи и учётные данные, секреты (`.env`, `.ssh`, профили браузеров, диск `Env:`), защита (антивирус, фаервол, BitLocker), удаление логов и все векторы уклонения (`iex`, `Invoke-Command`, вложенные `powershell`/`cmd`, `-EncodedCommand`, `Add-Type`, прямой доступ к .NET/COM, определение функций и алиасов). Даже с подтверждением не выполняется: для этого есть консоль на ПК.

Удаление **ограничено путём**: `Remove-Item` (и `rm`, `del`, `rmdir`...) разрешён внутри папки проекта — кодовому агенту нужно уметь удалять `node_modules` — и заблокирован снаружи. Удаление всего проекта (`.`) или `.git` требует подтверждения.

**Почему** (инцидент 2026-10-07): `/sh opencode service restart` убил процесс, хостящий плагин; поскольку offset полла хранился только в памяти, Telegram пересылал update при каждом рестарте, и сервер ушёл в цикл ~10 c, пока плагин не отключили руками. Персистентный offset — лекарство; этот гард — профилактика.

### /note

**Что делает**: Оставляет заметку в транскрипте — агент прочитает её следующим ходом, не просыпаясь сейчас.

**Использование**: `/note <текст>`

**Примеры**:
- `/note Приоритизировать модуль продаж` → агент видит это как контекст

**Заметки**: Это синтетическое сообщение — оно не запускает агента.

### /turns

**Что делает**: Что поменяли ходы сессии — тоньше, чем `/git`.

**Использование**: `/turns` или `/turns <ses_id>`

**Примеры**:
- `/turns` в треде → изменения по ходам

**Заметки**: Может быть пустым, если сервер не записал смен ходов.

## Проект и конфиг

### /config

**Что делает**: Читает и редактирует `opencode.jsonc` проекта — модель по умолчанию для новых сессий.

**Использование**: `/config` или `/config model <провайдер/модель>`

**Примеры**:
- `/config` → показывает текущий конфиг
- `/config model nvidia/z-ai/glm-5.3` → меняет дефолт (перезагружает на лету)

**Заметки**: Изменение касается НОВЫХ сессий — рестарт сервера не нужен.

### /worktree

**Что делает**: Перечисляет worktree проекта или создаёт новый.

**Использование**: `/worktree` или `/worktree new <имя>`

**Примеры**:
- `/worktree` → список с кнопками, открывающими сессии в каждом worktree
- `/worktree new feature-x` → создаёт worktree

**Заметки**: Тапни worktree, чтобы открыть в нём сессию.

### /move

**Что делает**: Переносит сессию в другой проект.

**Использование**: `/move <директория>`

**Примеры**:
- `/move E:\Projects\Other` → сессия из треда переезжает в этот проект

**Заметки**: Тред в Telegram остаётся прежним — меняется только рабочая директория.

### /mcp

**Что делает**: Перечисляет серверы MCP или подключает/отключает один.

**Использование**: `/mcp` или `/mcp connect|disconnect <server>`

**Примеры**:
- `/mcp` → список со статусом (🟢 подключён / 🔴 нет)
- `/mcp disconnect abap-docs` → отключает его
- `/mcp connect abap-docs` → подключает обратно

**Заметки**: Добавление нового сервера (PUT) остаётся за ПК.

### /commands

**Что делает**: Перечисляет кастомные команды из конфига или выполняет одну.

**Использование**: `/commands` или `/commands run <текст>`

**Примеры**:
- `/commands` → список (init, review и т.д.)
- `/commands run init` → выполняет команду «init» в сессии из треда

**Заметки**: Кастомные команды определяются в `opencode.jsonc` проекта.

## Информация и отладка

### /locale

**Что делает**: Меняет язык бота — меню `/help`, карточки и все сообщения переключаются мгновенно.

**Использование**: `/locale` (с кнопками) или `/locale <es|en|pt|de|fr|it|id|ru>`

**Примеры**:
- `/locale` → карточка с кнопкой на каждый язык (текущий с ✓)
- `/locale ru` → меняет напрямую; подтверждение приходит НА выбранном языке

**Заметки**: Выбор хранится в `~/.opencode/tg/locale.txt` — рестарт его не теряет. `TG_LOCALE` в `.env` — лишь начальное значение. Новый язык — это новый объект в `CATALOGS` (src/locale.ts) плюс свой `COMMANDS.<язык>.md` — никакого дополнительного кода.

### /bots

**Что делает**: Показывает раскладку мульти-бота: какой бот зеркалит какой проект или сессию, кто свободен, и главный бот (хаб), покрывающий всё остальное.

**Использование**: `/bots`

**Примеры**:
- `/bots` → по строке на бота с его клеймом (проект, сессия или «свободен») и активной топологией

**Заметки**: Дополнительные боты объявляются как `TELEGRAM_BOT_TOKEN_<ИМЯ>` в `~/.opencode/tg/.env` — никогда в репозитории. Топология (`single` / `per-project` / `per-session`) и явный маппинг (`assign`) живут в блоке `"bots"` файла `config.json`. С одним ботом карточка объясняет, как добавить ещё. Каждому дополнительному боту нужны включённые topics в BotFather, как и основному.

### /release

**Что делает**: Возвращает ЭТОГО бота в пул — только в топологии `per-session`. Его сессия уходит на хаб, пока её не потребует другой.

**Использование**: `/release` (из чата бота, который хочешь освободить)

**Примеры**:
- `/release` → «🧹 освобождён — его сессия возвращается на хаб»

**Заметки**: Бот также возвращается сам, когда архивируешь (`/archive`) сессию, державшую его. В `single` и `per-project` команда отвечает, что не применима. При реактивации сессии её следующий ход сам займёт свободного бота.

### /context

**Что делает**: Токены, стоимость, лимит модели и сжатия сессии.

**Использование**: `/context` или `/context <ses_id>`

**Примеры**:
- `/context` в треде → использование контекста этой сессии

**Заметки**: Модель восстанавливается из транскрипта, если сервер не сообщает её в payload.

### /usage

**Что делает**: Токены и стоимость сессии — с провайдером и моделью.

**Использование**: `/usage` или `/usage <ses_id>`

**Примеры**:
- `/usage` в треде → `🧪 nvidia · z-ai/glm-5.3 · агент build` + токены

**Заметки**: Модель и агент восстанавливаются из транскрипта, когда payload их забывает.

### /history

**Что делает**: Конец разговора сессии.

**Использование**: `/history` или `/history <ses_id>`

**Примеры**:
- `/history` в треде → последние 16 сообщений

**Заметки**: Читает с сервера (активная сессия) или из транскрипта на диске.

### /log

**Что делает**: Фрагмент серверного лога сессии.

**Использование**: `/log` или `/log <ses_id>`

**Примеры**:
- `/log` в треде → последние 10 событий лога

**Заметки**: Это окно чтения — не полный лог.

### /ci

**Что делает**: Показывает последние запуски GitHub Actions репозитория — какой workflow, на каком коммите, и зелёный или красный. То, что доказывает, что push дошёл целиком: typecheck, набор тестов и, дважды в неделю, печать зависимостей.

**Использование**: `/ci`, `/ci <n>` или `/ci <workflow>`

**Примеры**:
- `/ci` → последние 6 запусков со статусом и ссылкой на sha
- `/ci 12` → последние 12
- `/ci deps` → только запуски workflow `deps-audit`

**Заметки**: Читает REST API GitHub без зависимостей. Репозиторий публичный, поэтому работает без токена (60 запросов/час с IP); `GITHUB_TOKEN` в `~/.opencode/tg/.env` поднимает лимит и достаёт приватные репозитории. Репозиторий по умолчанию — `par4987/opencode-tg`; форк меняет его через `"ci": { "repo": "owner/repo" }` в `config.json` или `TG_CI_REPO`.

### /terminal

**Что делает**: Терминал сессии, только чтение.

**Использование**: `/terminal` или `/terminal <ses_id>`

**Примеры**:
- `/terminal` в треде → последние строки терминала

**Заметки**: Появляется, когда агент запускает что-то интерактивное. Управление остаётся на ПК.

### /perms

**Что делает**: Перечисляет сохранённые разрешения «всегда» или отзывает одно.

**Использование**: `/perms` или `/perms del <id>`

**Примеры**:
- `/perms` → накопленные «🔁 Всегда»
- `/perms del psv_xxx` → отзывает одно

**Заметки**: Отзыв заставляет сервер спросить снова.

### /sessions

**Что делает**: Сессии, известные серверу.

**Использование**: `/sessions`

**Примеры**:
- `/sessions` → список со статусом (🎯 активна, 📡 зеркало, 💤 idle)

### /running

**Что делает**: Сессии с выполняемым сейчас ходом.

**Использование**: `/running`

**Примеры**:

## Чат и очередь

### /queue

**Что делает**: Ожидающие сообщения в инбоксе сессии.

**Использование**: `/queue` или `/queue <ses_id>`

**Примеры**:
- `/queue` → список с переупорядочиванием (↑↓), продвижением (▶), отменой (✖), заменой (✏️)

**Заметки**: Пункты сжатия и перемещения уже размечены.

### /flush

**Что делает**: Проталкивает в текущий ход всё, что инбокс придерживает.

**Использование**: `/flush` или `/flush <текст>`

**Примеры**:
- `/flush` → вывалить инбокс в ход
- `/flush сделай X` → внедряет текст в ход СЕЙЧАС

**Заметки**: С текстом это прямой стеринг — входит в выполняемый ход.

### /clearqueue

**Что делает**: Отменяет все ожидающие сообщения инбокса.

**Использование**: `/clearqueue` или `/clearqueue <ses_id>`

**Примеры**:
- `/clearqueue` → отменяет всё

### /send

**Что делает**: Отправляет промпт в сессию откуда угодно.

**Использование**: `/send <текст>` или `/send <ses_id> <текст>`

**Примеры**:
- `/send сделай выжимку` → уходит в сессию из треда
- `/send ses_xxx сделай X` → уходит в эту сессию

### /txt

**Что делает**: Свободный ответ на открытый вопрос агента.

**Использование**: `/txt <ответ>`

**Примеры**:
- `/txt Вариант B` → отвечает на активный вопрос

### /menu

**Что делает**: Меню команд с кнопками.

**Использование**: `/menu`

**Примеры**:
- `/menu` → клавиатура с основными командами

### /help

**Что делает**: Перечисляет команды с меню для просмотра подробностей по каждой.

**Использование**: `/help`

**Примеры**:
- `/help` → краткий список + клавиатура
- Тапни команду → её подробный раздел (что делает, использование, примеры, заметки)

### /watch

**Что делает**: Управляет тем, какие сессии наблюдает чат.

**Использование**: `/watch <id|all|off>`

**Примеры**:
- `/watch all` → следить за всем
- `/watch ses_xxx` → следить только за ней
- `/watch off` → ни за кем не следить

**Заметки**: При `mirror: all` в конфиге `/watch <id>` глушит остальных.
