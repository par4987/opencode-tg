# 명령 참고

각 명령이 무엇을 하는지, 사용법, 예시, 참고. Telegram의 `/help` 메뉴가 같은
명령을 제공해요 — 하나를 누르면 해당 섹션을 받아요.

## 세션

### /new

**역할**: 선택한 프로젝트에 새 세션을 만들고, Telegram 스레드가 곧바로 열려요.

**사용**: `/new <제목?>`

**예시**:
- `/new 매출 분석` → 프로젝트 선택기를 보여요; 하나를 누르면 "매출 분석" 세션이 그곳에 만들어져요
- `/new` → 채팅에서 제목을 물어보고, 주어지면 선택기를 보여요

**참고**:
- 현재 대화의 프로젝트가 선택기 첫 번째에 와요 (✅) — 기본값이에요: 한 번 누르면 끝.
- "➕ 새 프로젝트…"가 이름을 물어보고 현재 프로젝트 옆에 그 폴더를 만들어요; 세션은 그 안에 열려요.
- 스레드는 만드는 순간 열려요 (예전에는 첫 메시지와 함께 태어났어요): 안에 적으면 세션이 이미 듣고 있어요.
- 새 스레드에서 프로바이더와 모델을 골라요: 프로젝트 기본 모델의 프로바이더에서 열리고, 그 모델은 ✅로 표시돼요 — 한 번 눌러 유지하거나 다른 것으로 둘러봐요. 나중에 `/models`로도 같아요.
- `/new`를 제목 없이 보내면, 그 스레드에 10분 안에 적는 다음 메시지가 이름이 돼요.

### /use

**역할**: 채팅 루트의 메시지가 어느 세션으로 가는지 정해요.

**사용**: `/use <ses_id>`

**예시**:
- `/use ses_f2a05826affeXDqtDAtfF23Rud` → 루트가 그 세션을 가리켜요
- `/use` → 현재 세션을 보여요

**참고**: 스레드 안의 메시지는 항상 그 스레드의 세션으로 가고, `/use`와 상관없어요.

### /fork

**역할**: 세션을 마지막 메시지까지 포크해요 — 원본을 더럽히지 않고 아이디어를 시도해요.

**사용**: `/fork` (스레드에서) 또는 `/fork <ses_id>`

**예시**:
- 세션의 스레드에서 `/fork` → 포크를 만들고 알려줘요
- `/fork ses_xxx` → 어디서든 같아요

**참고**: 포크는 자기 스레드가 있는 새 세션이에요. 원본은 그대로 남아요.

### /rename

**역할**: 세션의 이름을 바꿔요 — Telegram 스레드와 데스크톱이 따라가요.

**사용**: `/rename <제목>` 또는 `/rename <ses_id> <제목>`

**예시**:
- `/rename Q4 분석` → 스레드의 세션 이름을 바꿔요
- `/rename` (제목 없이) → 트랜스크립트에서 제목 3개를 추천하고 하나를 골라요

**참고**: 제목은 128자로 잘려요 (Telegram 토픽 이름의 한도).

### /detach

**역할**: 채팅 루트를 세션에서 떼어 놓어요 — 거기에 적는 것은 더 이상 어떤 세션으로도 가지 않아요.

**사용**: `/detach`

**예시**:
- `/detach` → 루트가 자유로워져요
- `/use <ses_id>` → 다시 연결돼요

**참고**: 세션 스레드는 영향을 받지 않아요.

### /archive

**역할**: 스레드의 세션을 보관해요 — 개인 채팅에서는 스레드를 지우고 세션을 음소거해요.

**사용**: `/archive` 또는 `/archive <ses_id>`

**예시**:
- 스레드에서 `/archive` → 스레드가 채팅에서 사라져요
- `/archive ses_xxx` → 어디서든 같아요 (id는 고유 접두사를 받아요)

**참고**: `/unarchive`가 다시 가져와요 — 단독으로 쓰면 보관된 것의 선택기를 열어서 id가 필요 없어요.

### /unarchive

**역할**: 보관된 세션을 깨워요 — id 없으면 선택기를 열고, 텍스트가 있으면 프로젝트, 제목 또는 id로 찾아요.

**사용**: `/unarchive`, `/unarchive <텍스트>` 또는 `/unarchive <ses_id>`

**예시**:
- 루트에서 `/unarchive` → 보관된 세션의 선택기를 열어요, 최근 것이 먼저
- `/unarchive 청구서` → 일치하는 것 (제목, 프로젝트 또는 id)의 선택기
- `/unarchive ses_ed2c` → 접두사로 id를 해석하고 바로 깨워요
- 살아 있는 스레드에서 `/unarchive` → 그 세션은 보관되지 않았다고 알려요

**참고**:
- id 없이도 맞힐 필요 없어요: 선택기가 보관된 것을 버튼으로 나열해요 (제목 · 프로젝트 · 활동), 한 페이지에 8개.
- `<텍스트>`는 **프로젝트** (폴더 이름), 제목 또는 id 접두사로 찾아요.
- id는 전체 또는 고유 접두사 형태를 받고, 대소문자를 구분하지 않아요.
- 스레드가 지워졌다면, 현재 제목으로 새 것을 만들어요.
- 개인 채팅에서 `/archive`가 스레드를 지우므로, `/unarchive`가 그것을 다시 만들어요; PC의 세션은 절대 건드리지 않아요.

### /delthread

**역할**: 포럼 스레드를 지우되 세션은 건드리지 않아요.

**사용**: `/delthread` 또는 `/delthread <ses_id>`

**예시**:
- 스레드에서 `/delthread` → 스레드가 사라져요

**참고**: 세션은 계속 존재해요 — 다음 이벤트가 스레드를 다시 만들어요. 음소거하려면: `/archive`. id는 고유 접두사를 받고, 대소문자를 구분하지 않아요.

### /rebuild

**역할**: 세션 스레드 전부를 지우고 포럼을 깨끗하게 다시 세워요.

**사용**: `/rebuild` (인라인 확인과 함께)

**예시**:
- `/rebuild` → 매핑된 스레드를 (하나씩, 확인하며) 지우고 최근에 쓴 세션의 것을 다시 만들어요 (최대 12개, 최근 것이 위에)

**참고**: 오래된 메시지는 다시 가져오지 않아요 — `/export`가 각 세션의 트랜스크립트를 내려요. `rebuildIdleHours` (기본 24시간) 안에 쓴 세션의 스레드만 다시 만들어요: 서버가 재시작할 때 모든 세션의 `updated` 필드를 덮어쓰므로, 그것으로 정렬하면 아무도 며칠 동안 만지지 않은 세션이 살아나버렸어요; `idle`이 진짜 마지막 활동이에요. 각 삭제는 매핑을 잊기 전에 확인돼요 — Telegram이 하나를 거절하면 (속도 제한, 끊김) 스레드는 매핑된 채로 남고 다음 `/rebuild`가 다시 시도해요; 스레드가 살아남은 세션은 복제되지 않아요. **고아** 스레드 (매핑 없는)는 스스로 청소되지 않아요: Bot API에 "토픽 목록"이 없으므로, 한 번은 손으로 지워야 해요.

## 파일과 코드

### /ls

**역할**: 세션 프로젝트의 파일을 둘러보고 열어요.

**사용**: `/ls [폴더]`

**예시**:
- `/ls` → 프로젝트 루트 디렉터리를 나열해요
- `/ls src` → src 폴더로 들어가요
- 파일을 누르면 → 다운로드돼요
- 텍스트 파일의 📎 → 다음 메시지에 첨부돼요

**참고**: 버튼의 인덱스는 만료돼요 — 눌렀는데 "리스팅이 오래됐어요"라고 하면 `/ls`을 다시 열어요.

### /find

**역할**: 이름으로 파일을 흐릿하게 찾아요.

**사용**: `/find <텍스트>`

**예시**:
- `/find navbar` → 이름에 "navbar"가 든 파일
- `/find .test.` → 이름에 ".test."가 든 파일

**참고**: 세션 프로젝트 전체에서 찾아요.

### /git

**역할**: 에이전트가 프로젝트에서 무엇을 했는지 — `+/−`가 있는 상태와 내려받을 수 있는 diff.

**사용**: `/git`

**예시**:
- `/git` → 프로젝트 상태
- "diff 보기" → 미리보기 + 내려받을 수 있는 `.patch`

**참고**: 세션의 diff가 아니라 프로젝트의 diff예요 — 여러 에이전트가 공유할 수 있어요.

### /revert

**역할**: 세션의 마지막 턴을 되돌려요 (확인과 함께).

**사용**: `/revert` 또는 `/revert <ses_id>`

**예시**:
- 스레드에서 `/revert` → 마지막 턴을 되돌리겠다고 제안해요
- 버튼으로 확인 → 턴이 되돌아가요

**참고**: 마지막 턴만 되돌려요. 여러 개: `/revert` 반복.

### /export

**역할**: 세션의 전체 트랜스크립트를 JSON으로 내려받아요.

**사용**: `/export` 또는 `/export <ses_id>`

**예시**:
- 스레드에서 `/export` → 트랜스크립트의 JSON이 도착해요
- `/export ses_xxx` → 어디서든 같아요

**참고**: 세션이 PC에 열려 있으면 내보내기가 완전해요. 닫혀 있으면 디스크에 트랜스크립트가 없을 수 있어요 (서버의 지속성 결함).

### /sh

**역할**: 세션 **안에서** 셸 명령을 실행해요 — 백그라운드에서, 에이전트를 깨우지 않고.

**사용**: `/sh <명령>`

**예시**:
- `/sh node -v` → `v24.21.0`
- `/sh git status` → 저장소 상태
- `/sh ls` → 디렉터리 내용

**참고**: 세션의 셸은 PowerShell이에요 — `&&`는 작동하지 않고, `;`을 써요. 출력은 스레드에 와요.

**보호되는 명령**: 명령은 **파싱**돼요 (정규식으로 찾지 않아요: 진짜 이름으로, 별칭이 풀린 채로)고 세 단계 중 하나에 떨어져요:

- **곧바로 통과**: 순수 읽기 (`Get-*`, `Test-*`, `ls`, `cat`)와 개발 도구 체인 (`git`, `node`, `npm`, `cargo`, `python`...). 여기서 거짓 양성이 나오면 봇이 매 `git status`마다 확인을 요구하게 돼요.
- **확인 요구**: 복구 가능하지만 서비스를 끊거나 기계 밖으로 나갈 수 있는 것 — 서버 재시작, 프로세스 종료, 소프트웨어 설치, 네트워크 호출, 원격 실행, 예정 작업. 카드가 **각 명령이 무엇을 하는지 설명**해요 (일어날 일을, 텍스트만이 아니라)고 "확인하고 실행"을 눌러야 해요. 대기 항목은 실행 **전에** 지워져서, 충돌이 그것을 다시 촉발하지 않아요.
- **차단, 예외 없이**: 되돌릴 수 없는 것 — 디스크 포맷과 삭제, 부팅과 시스템 복구, 레지스트리, 사용자와 자격 증명, 비밀 (`.env`, `.ssh`, 브라우저 프로필, `Env:` 드라이브), 방어 (안티바이러스, 방화벽, BitLocker), 로그 삭제, 그리고 모든 회피 벡터 (`iex`, `Invoke-Command`, 중첩 `powershell`/`cmd`, `-EncodedCommand`, `Add-Type`, .NET/COM 직접 접근, 함수와 별칭 정의). 확인해도 실행되지 않아요: 그것은 PC 콘솔의 용도예요.

삭제는 **경로로 제한**돼요: `Remove-Item` (그리고 `rm`, `del`, `rmdir`...)은 프로젝트 폴더 안에서 허용돼요 — 코드를 짜는 에이전트는 `node_modules`를 지울 수 있어야 해요 — 바깥에서는 차단돼요. 프로젝트 전체 (`.`) 또는 `.git`을 지우는 것은 확인을 요구해요.

**이유** (2026-10-07 사건): `/sh opencode service restart`가 플러그인을 호스팅하는 프로세스를 죽였어요; poll의 오프셋이 메모리에만 있어서 Telegram이 매 재시작마다 update를 재전송했고, 서버가 ~10초짜리 루프에 빠졌다가 플러그인을 손으로 껐어요. 지속적인 오프셋이 치료고, 이 방어가 예방이에요.

### /note

**역할**: 트랜스크립트에 메모를 남겨요 — 에이전트는 다음 턴에 읽고, 지금 깨우지는 않아요.

**사용**: `/note <텍스트>`

**예시**:
- `/note 매출 모듈을 우선해` → 에이전트가 맥락으로 봐요

**참고**: 합성 메시지예요 — 에이전트를 실행하지 않아요.

### /turns

**역할**: 세션의 턴들이 무엇을 바꿨는지 — `/git`보다 더 세밀해요.

**사용**: `/turns` 또는 `/turns <ses_id>`

**예시**:
- 스레드에서 `/turns` → 턴들의 변경

**참고**: 서버가 턴 변경을 기록하지 않았으면 비어 있을 수 있어요.

## 프로젝트와 config

### /config

**역할**: 프로젝트의 `opencode.jsonc`를 읽고 편집해요 — 새 세션의 모델 기본값.

**사용**: `/config` 또는 `/config model <프로바이더/모델>`

**예시**:
- `/config` → 현재 config을 보여요
- `/config model nvidia/z-ai/glm-5.3` → 기본값을 바꿔요 (라이브로 다시 로드)

**참고**: 바꿈은 **새** 세션에 적용돼요 — 서버 재시작이 필요 없어요.

### /worktree

**역할**: 프로젝트의 워크트리를 나열하거나 새 것을 만들어요.

**사용**: `/worktree` 또는 `/worktree new <이름>`

**예시**:
- `/worktree` → 각 워크트리에 세션을 여는 버튼이 있는 목록
- `/worktree new feature-x` → 워크트리를 만들어요

**참고**: 워크트리를 누르면 그 안에 세션을 열어요.

### /move

**역할**: 세션을 다른 프로젝트로 옮겨요.

**사용**: `/move <디렉터리>`

**예시**:
- `/move E:\Projects\Otro` → 스레드의 세션이 그 프로젝트로 옮겨져요

**참고**: Telegram 스레드는 그대로예요 — 작업 디렉터리만 바뀌어요.

### /mcp

**역할**: MCP 서버를 나열하거나 하나를 연결/해제해요.

**사용**: `/mcp` 또는 `/mcp connect|disconnect <server>`

**예시**:
- `/mcp` → 상태가 있는 목록 (🟢 연결됨 / 🔴 아니요)
- `/mcp disconnect abap-docs` → 연결을 해제해요
- `/mcp connect abap-docs` → 다시 연결해요

**참고**: 새 서버 추가 (PUT)는 PC에 남아 있어요.

### /commands

**역할**: config의 사용자 지정 명령을 나열하거나 하나를 실행해요.

**사용**: `/commands` 또는 `/commands run <텍스트>`

**예시**:
- `/commands` → 목록 (init, review 등)
- `/commands run init` → 스레드의 세션에서 "init" 명령을 실행해요

**참고**: 사용자 지정 명령은 프로젝트의 `opencode.jsonc`에 정의돼요.

## 정보와 디버그

### /locale

**역할**: 봇의 언어를 바꿔요 — `/help` 메뉴, 카드, 모든 메시지가 즉시 따라가요.

**사용**: `/locale` (버튼과 함께) 또는 `/locale <es|en|pt|de|fr|it|id|ru|tr|zh|ko|ar>`

**예시**:
- `/locale` → 언어마다 하나씩 버튼이 있는 카드 (현재 것은 ✓)
- `/locale ko` → 곧바로 바뀌어요; 확인이 고른 언어로 와요

**참고**: 선택은 `~/.opencode/tg/locale.txt`에 유지돼요 — 재시작에 잃지 않아요. `.env`의 `TG_LOCALE`은 초기값일 뿐이에요. 새 언어는 `CATALOGS` (src/locale.ts)의 새 객체와 그 `COMMANDS.<언어>.md`일 뿐 — 추가 코드가 없어요.

### /bots

**역할**: 멀티봇 배치를 보여요: 어느 봇이 어느 프로젝트나 세션을 미러링하는지, 누가 한가한지, 나머지 전부를 덮는 메인 봇 (허브).

**사용**: `/bots`

**예시**:
- `/bots` → 봇마다 한 줄, 자기 할당 (프로젝트, 세션 또는 "한가")과 활성 토폴로지와 함께

**참고**: 추가 봇은 `~/.opencode/tg/.env`에 `TELEGRAM_BOT_TOKEN_<이름>`으로 선언돼요 — 절대 저장소에 넣지 않아요. 토폴로지 (`single` / `per-project` / `per-session`)와 명시적 할당 (`assign`)은 `config.json`의 `"bots"` 블록에 살아요. 봇 하나일 때, 카드가 또 하나를 더하는 법을 설명해요. 추가 봇마다 BotFather에서 topics를 켜야 해요, 메인과 같아요.

### /release

**역할**: **이** 봇을 풀에 돌려줘요 — `per-session` 토폴로지에서만. 세션은 다른 봇이 할당할 때까지 허브로 가요.

**사용**: `/release` (풀고 싶은 봇의 채팅에서)

**예시**:
- `/release` → "🧹 해제됨 — 세션이 허브로 돌아가요"

**참고**: 봇은 자기를 할당했던 세션을 보관 (`/archive`)할 때도 스스로 돌아와요. `single`과 `per-project`에서 명령은 해당사항 없음이라고 답해요. 세션이 다시 활성화되면, 다음 턴이 자동으로 한가한 봇을 할당해요.

### /context

### /ci

**역할**: 저장소의 최근 GitHub Actions 실행을 보여요 — 어느 워크플로, 어느 커밋에서, 초록인지 빨간지. 푸시가 온전히 도착했는지를 증명하는 것: 타입체크, 테스트 suites, 그리고 일주일에 두 번 의존성 도장.

**사용**: `/ci`, `/ci <n>` 또는 `/ci <워크플로>`

**예시**:
- `/ci` → 최근 6개 실행과 상태, sha로의 링크
- `/ci 12` → 최근 12개
- `/ci deps` → `deps-audit` 워크플로의 실행만

**참고**: 의존성 없이 GitHub REST API를 읽어요. 저장소가 공개라서 토큰 없이도 돼요 (IP당 시간당 60회); `~/.opencode/tg/.env`의 `GITHUB_TOKEN`이 한도를 올리고 비공개 저장소에 닿아요. 기본 저장소는 `par4987/opencode-tg`예요 — fork는 `config.json`의 `"ci": { "repo": "owner/repo" }` 또는 `TG_CI_REPO`로 바꿔요.

## 채팅과 큐

### /queue

**역할**: 세션 받은편지함의 대기 중인 메시지들.

**사용**: `/queue` 또는 `/queue <ses_id>`

**예시**:
- `/queue` → 재정렬 (↑↓), 앞당기기 (▶), 취소 (✖), 대체 (✏️)가 있는 목록

**참고**: 압축과 이동 항목은 이미 표시돼 있어요.

### /flush

**역할**: 받은편지함이 붙잡고 있는 모든 것을 현재 턴으로 앞당겨요.

**사용**: `/flush` 또는 `/flush <텍스트>`

**예시**:
- `/flush` → 받은편지함을 턴에 부어요
- `/flush X를 해` → 텍스트를 현재 턴에 **곧바로** 주입해요

**참고**: 텍스트가 있으면 직접 주입 (steering)이에요 — 현재 턴으로 들어가요.

### /clearqueue

**역할**: 받은편지함의 모든 대기 중인 메시지를 취소해요.

**사용**: `/clearqueue` 또는 `/clearqueue <ses_id>`

**예시**:
- `/clearqueue` → 전부 취소해요

### /send

**역할**: 어디서든 세션에 프롬프트를 보내요.

**사용**: `/send <텍스트>` 또는 `/send <ses_id> <텍스트>`

**예시**:
- `/send 요약해 줘` → 스레드의 세션으로 가요
- `/send ses_xxx X를 해` → 그 세션으로 가요

### /txt

**역할**: 에이전트의 열린 질문에 자유 답변을 해요.

**사용**: `/txt <답변>`

**예시**:
- `/txt B 옵션` → 활성 질문에 답해요

### /menu

**역할**: 버튼이 있는 명령 메뉴.

**사용**: `/menu`

**예시**:
- `/menu` → 주요 명령이 있는 키보드

### /help

**역할**: 명령을 나열하고 각각의 세부를 보는 메뉴를 제공해요.

**사용**: `/help`

**예시**:
- `/help` → 짧은 목록 + 키보드
- 명령을 누르면 → 그 세부 섹션 (역할, 사용, 예시, 참고)

### /watch

**역할**: 채팅에서 어느 세션을 모니터링하는지 제어해요.

**사용**: `/watch <id|all|off>`

**예시**:
- `/watch all` → 전부 모니터링해요
- `/watch ses_xxx` → 그것만 모니터링해요
- `/watch off` → 아무것도 모니터링하지 않아요

**참고**: config에서 `mirror: all`일 때, `/watch <id>`가 나머지를 조용하게 해요.
